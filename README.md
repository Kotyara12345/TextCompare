# TextCompare

Портативное GUI-приложение для сравнения двух текстов с подсветкой совпавших фрагментов. Работает на Windows, Linux и macOS. Зависимости — только стандартная библиотека Python.

## Возможности

- **Три режима сравнения** — по словам, по строкам, по символам.
- **Подсветка совпадений зелёным и различий красным** в обеих панелях одновременно; подсветка применяется порциями с прогрессом и возможностью отмены.
- **Опция учёта регистра** — «Привет» и «привет» считаются совпадением по умолчанию.
- **Загрузка из файлов** с автоматическим определением кодировки (BOM → UTF-8 → CP1251 с предупреждением).
- **Статистика совпадений** — сколько символов совпало в каждом тексте (в штуках и процентах).
- **Навигация** — поиск Ctrl+F, переходы к различиям Alt+↓/Alt+↑ с подсветкой-вспышкой, синхронная прокрутка панелей, зум Ctrl+колесо.
- **Работа с панелями** — обмен местами, сохранение панели в файл, экспорт отчёта в HTML.
- **Настройки запоминаются** между запусками (режим, регистр, шрифт, прокрутка, различия).
- **Горячие клавиши в любой раскладке** — Ctrl+V/C/X/A/Z/Y работают и при включённой русской (или другой нелатинской) раскладке, несмотря на баг Tk ≤ 8.6.15; пункты меню и Ctrl+O/S/F, F5 тоже.
- **Отзывчивый интерфейс** — тяжёлые вычисления в фоновом потоке, чанкованная вставка больших файлов, кнопка «Отмена» срабатывает мгновенно; правка текста после сравнения сразу сбрасывает устаревшую подсветку.
- **Надёжность** — файловый лог с ротацией и перехват необработанных исключений (критично для `--windowed`-сборки без консоли).
- **Портативная сборка** — один `.exe` без зависимостей и установки.

## Установка и запуск

### Из исходников

Требуется Python 3.9 или новее. Внешних зависимостей нет.

```bash
git clone https://github.com/<your-username>/text-compare.git
cd text-compare
python text_compare.py
```

### Сборка портативного `.exe`

```bat
pip install pyinstaller
pyinstaller --onefile --windowed --name TextCompare text_compare.py
```

Готовый `dist\TextCompare.exe` (~10 МБ) запускается на любой Windows без установленного Python.

## Использование

1. **Вставьте тексты** в две панели вручную или нажмите «Открыть файл» — кодировка определится автоматически.
2. **Выберите режим:**
   - **По словам** — для обычных текстов, статей, документации.
   - **По строкам** — для логов, конфигов, исходного кода.
   - **По символам** — для поиска мелких вставок в почти одинаковых строках (на текстах больше ~30 тыс. символов появится предупреждение о медленном расчёте).
3. **Нажмите «Сравнить»** (F5 или Ctrl+Enter) — совпадения подсветятся зелёным, различия — красным.
4. **Смотрите статистику** в статус-баре: сколько символов совпало в каждом тексте.
5. **Перемещайтесь** — Alt+↓/Alt+↑ к следующему/предыдущему различию (с «вспышкой»), Ctrl+F — поиск, Ctrl+колесо — зум.
6. **Экспорт** — «Файл → Экспорт результата в HTML…» для отчёта, Ctrl+S — сохранить панель в `.txt`, «Правка → Поменять тексты местами» — обмен панелей.
7. **«Отмена»** (Esc) — прерывает сравнение и подсветку. Кнопки возвращаются в рабочее состояние мгновенно, фоновые вычисления завершаются тихо и не публикуют результат.

## Как это работает

### Архитектура

```
read_text_file()          — I/O, определение кодировки
_Cancelled, Match, TkMap  — типы и внутренние сигналы
TextDiffer                — чистая логика сравнения, без tkinter
TextComparator            — GUI, потоки, обмен с UI
main()                    — точка входа
```

`TextDiffer` не зависит от tkinter и легко тестируется в изоляции или переиспользуется в CLI/бэкенде.

### Алгоритм

1. Текст разбивается на **токены** в зависимости от режима (слова / строки / символы).
2. Гиперчастые токены (пробелы, повторы строк) **исключаются из сопоставления** — иначе `difflib.SequenceMatcher` уходит в квадратичность на обычных текстах (замеры на 20 КБ: свыше 10 минут до фикса против ~1 секунды после). Совпавшие промежутки вокруг исключённых токенов сшиваются обратно, когда текст по обе стороны совпадает, поэтому подсветка не «рвётся» на пробелах.
3. `SequenceMatcher` ищет общие блоки по «сжатым» последовательностям токенов.
4. Диапазоны совпадений применяются к обоим `tk.Text` **порциями** — за один такт `after` красится группа блоков, размер порции адаптируется по времени (8–1024 блока). Прогресс виден в статусе, подсветку можно отменить.
5. Если в текстах есть astral-символы (эмодзи, CJK ext.), строится карта `py_index → tk_index` — иначе подсветка съехала бы на позициях таких символов.

### Многопоточность

- Все вычисления сравнения — в фоновом потоке.
- Обмен с UI — только через `queue.Queue(maxsize=1)` с вытеснением устаревших сообщений.
- UI-поток забирает результаты раз в 60 мс через `after`.
- `cancel()` синхронно восстанавливает кнопки — UI отзывчив независимо от того, где застрял воркер.
- Поддерживается до 3 одновременных сравнений; результаты устаревших прогонов отбрасываются по `run_id`.

### Обработка больших файлов

- **Чтение** — в фоновом потоке.
- **Вставка в `tk.Text`** — порциями по 500 000 символов с `after(1, ...)` между ними, чтобы UI оставался отзывчивым.
- **Сравнение** — soft-warning в статусе при текстах > 2 млн символов, а в посимвольном режиме — уже с ~30 тыс. символов.
- **Warning в лог** при файлах > 5 МБ.

## Логи

Пишутся автоматически:

- Windows: `%TEMP%\text_compare.log`
- Linux/macOS: `/tmp/text_compare.log`

Формат: время, уровень, имя потока, сообщение. Полный traceback при ошибках в воркерах — критично для `--windowed`-сборок, где нет консоли.

## Известные ограничения

- **`SequenceMatcher.get_matching_blocks()` прерывается только снаружи** — «Отмена» срабатывает до и после вызова, но не внутри: difflib не даёт чекпоинтов. Гиперчастые токены исключаются заранее (см. «Алгоритм»), поэтому на типичных текстах вызов занимает миллисекунды, но тонкие различия внутри самих частых токенов могут не подсвечиваться отдельно. Для жёсткой отменяемости мегабайтных сравнений нужен `rapidfuzz` или собственный Myers с чекпоинтами — вне рамок текущей задачи.
- **Оба текста читаются целиком в память.** Это свойство текстового сравнения: `SequenceMatcher` требует обе последовательности. `LARGE_TEXT_BYTES = 5 МБ` даёт сигнал в лог, но не блокирует.
- **Определение кодировки без сторонних библиотек.** После провала UTF-8 мы не можем отличить CP1251 от CP866 или KOI8-R — файл декодируется как CP1251 с явным предупреждением в статус-баре.
- **`MAX_LIVE_WORKERS = 3`** — эмпирический лимит на одновременные сравнения. Защищает от накопления потоков, если пользователь многократно нажимает «Сравнить», пока предыдущий прогон застрял на неделимом C-вызове.

## Разработка

Код полностью типизирован, совместим с Python 3.9+ (используются PEP 585 дженерики `list[...]` / `dict[...]` и `Optional`/`Union` для runtime-алиасов). Работает с `mypy --strict` и `pyright` в базовом режиме.

Разделение на слои позволяет тестировать `TextDiffer` в изоляции — без `tkinter`, без потоков, без файловой системы:

```python
from text_compare import TextDiffer
import threading

t1 = "Hello, world!"
t2 = "Hello, python!"

matches = TextDiffer.compute_matches(
    t1, t2, mode="words",
    case_sensitive=False,
    cancel=threading.Event(),
)
# [(0, 7, 0, 7)]  — "Hello, " совпало в обоих
```
